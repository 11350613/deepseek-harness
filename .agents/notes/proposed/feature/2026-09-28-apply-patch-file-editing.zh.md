# Agent Note: Apply patch 文件编辑

Status: proposed

[English](2026-09-28-apply-patch-file-editing.md) | 中文

## 问题

模型编辑多个文件或相隔较远的区域时，需要多次字面量编辑调用或一段 shell 脚本。Shell 和 Python 编辑不会向现有文件工具采集路径暴露受影响文件，因此没有 Git 的工作目录无法可靠地在轮次 Review tab 中展示这些修改。补丁工具可以在一次调用中表达相关编辑，并在修改前识别所有受影响路径。#5121 先实现工具再评测效果；#4556 提供了高效使用文件工具的更广泛动机。

## 提案

新增 `apply_patch` 工具，支持文本文件的创建、更新、删除和移动，以及一次调用中的多文件、多 hunk 修改。采用 Codex 补丁语法，复用现有文件系统能力、观察策略、沙箱策略和工具执行生命周期。将解析与路径提取放在共享的纯模块中，使执行与 Review 采集对同一补丁保持一致理解。

Review 工作仅限于在修改前采集工具涉及的路径，以及添加必要的组合或配置项。复用现有[工作区变更记录器](../../../../packages/deliverables/workspace-changes/README.zh.md)和 [Review tab](../../../../packages/client/ui-deliverables/README.zh.md)，包括其 diff 类型和展示逻辑。移动可以显示为删除加创建。重命名专用展示、Review 持久化存储、远程采集，以及采集限制或失败策略的调整均不在本提案范围内。

### 已确认的设计选择

以下设计选择已获确认。完整工具仍处于提案阶段；纯解析器和文本匹配器已在 [dsh-fs-patch](../../../../packages/fs/fs-patch/README.zh.md) 中实现，以 Codex `rust-v0.158.0` 为语法和匹配参照；受保护的文件系统操作已在 [dsh-fs](../../../../packages/fs/fs/README.zh.md) 及其提供方实现。预检与顺序执行器已在 [dsh-tool-fs](../../../../packages/fs/tool-fs/README.zh.md) 中实现。包 README 维护支持行为与排除项；工具注册与呈现仍处于提案阶段。

| 主题 | 已确认方案 | 实现规范 |
|---|---|---|
| 输入 | 使用包含 `patch` 字符串的 JSON 参数；适用时复用文件系统权限字段。 | 最终参数 schema、启用方式，以及有输出上限的结果字段。 |
| 语法 | `*** Begin Patch`、`*** End Patch`、`*** Add File:`、`*** Update File:`、`*** Delete File:`、`*** Move to:`、hunk 标记和 `*** End of File`。 | 选择上游 Codex 版本，列出支持形式、非法输入及排除项。 |
| 匹配 | 遵循固定版本 Codex 的解析器和匹配器。 | 核对参照实现的精确匹配、空白容错、Unicode 归一化、重复上下文、搜索顺序、空 hunk 和 EOF 行为；每项记录预期输出或错误。 |
| 文件系统策略 | 保留已挂载的观察与沙箱策略；内部预检读取不算模型观察。 | 在这些策略下细化更新、删除和移动的保护条件与目标冲突，以及路径别名、重复路径、跨提供方移动和换行符保留规则。 |
| 失败 | 先预检整个补丁，再按顺序提交；首次失败即停止，报告实际完成、失败和未执行的操作；不提供整个补丁回滚。 | 各操作的提交点、取消，以及目标已写入但源文件未删除时的移动结果。 |
| 启用 | 通过组合配置启用以进行实现和评测，同时保留现有文件工具。 | 首批暴露工具的 profile；扩大默认启用范围以评测结果为依据。 |

补丁语法与文本匹配遵循选定的 Codex 版本。先读后改、版本新鲜度检查和沙箱限制仍属于 Harness 部署策略。兼容性矩阵记录这些策略差异和已核实的参照行为，是实现规范，不再将匹配策略列为待选择项。

### 开发计划

我们按顺序实现并验证各步骤。解析器提供匹配、执行与采集共用的记录。步骤 1–6 完成后进行步骤 7 的集成验收；步骤 8 的评测在验收后开始。

1. **实现补丁解析与受影响路径收集。** 新增 `packages/fs/fs-patch` 纯库，不依赖工具、Session 或文件系统提供方。固定 Codex 语法参照并保留适用的许可声明。定义可序列化的操作和 hunk；实现携带原始输入行号错误的 `parsePatch(patch)`，以及包含移动两端的 `collectMutationPaths(operations)`。保留操作顺序和重复操作，只对收集的路径字符串去重。不进行文件系统 I/O，覆盖单文件、多文件、多 hunk、移动、非法输入及参照语法用例。

2. **实现 hunk 匹配与文本更新。** 在同一纯库中将解析出的 hunk 应用于调用方提供的文本。精确匹配、空白容错、Unicode 归一化、重复上下文、搜索顺序及 EOF 行为遵循固定版本的 Codex 匹配器。覆盖 LF/CRLF、缺少末尾换行、空文件与无法匹配的 hunk；记录有意差异和预期结果。文件读取、权限检查和提交不属于此步骤。

3. **补齐受保护的文件系统操作。** 当前[文件系统服务](../../../../packages/fs/fs/README.zh.md)提供文本写入和字面量编辑，没有删除或移动操作。只添加选定补丁设计需要的原语，保留提供方负责的版本新鲜度检查和单文件原子发布。同时更新本地、沙箱和 [SSH 文件系统](../../../../packages/ssh/fs-ssh/README.zh.md)实现，以及受影响的 RPC helper/schema 消费方。移动涉及两个路径，必须明确定义锁、源与目标保护条件及失败结果。退出条件：旧版本、受限路径、目标冲突和中断操作都留下约定的磁盘状态；不宣称多文件事务。

4. **实现补丁执行。** 解析并去重规范化目标，获取策略意图，在修改前预检语法、权限、匹配及目标规则。每次由提供方提交时重新检查版本新鲜度；预检不能消除后续竞态或 I/O 失败。按顺序执行，在实际修改后更新观察状态，并在取消或后续失败时保留已完成操作的事实。退出条件：结果元数据和精简模型输出与磁盘状态一致，包括部分完成的移动；执行器不通过 shell 或直接写 Host 文件绕过文件系统提供方。

5. **暴露并呈现工具。** 通过常规插件 effect 和现有工具/PTC 路径注册 `apply_patch`，保持 agent loop 不变。将参数规则放入 schema，说明何时选用工具，并提供简短的纠错信息。使用现有结果元数据和呈现机制设计 Host presenter 与 Web 工具调用展示。添加选定的启用/配置项，对缺失依赖给出明确错误。退出条件：目标 profile 能声明并执行工具，未启用的 profile 保持一致，所有模型可见输出均可由 Session 日志重建。

6. **接入现有 Review 采集。** 记录器的[修改路径提取](../../../../packages/deliverables/workspace-changes/src/capture.ts)目前只识别固定工具，并返回单一路径。为 `apply_patch` 增加最小的生产端适配，从共享解析器枚举全部受影响路径，包括移动的源与目标。在任何写入前等待基线采集完成，并保留每个路径在轮次中的首次采集。复用轮次结束时对实际字节的采集与比较。退出条件：无 Git 目录能展示所有支持范围内存在净变化的文件，重复编辑形成从首次修改前到最终状态的 diff，失败或未执行操作不产生虚假变更，Review 展示代码不变。这里需要小幅修改路径提取；当前仅靠配置不能实现。

7. **验证组合能力并补齐文档。** 将定向解析器、提供方和工具测试，与通过已发布 profile 的录制 Session 快照、无 Git 目录中的现有 Review 流程结合。覆盖成功修改、预检拒绝、部分执行、取消及现有工具回归。如果快照测试框架无法表达必要路径，在同一实现中补齐支持。更新受影响的双语 README、JSDoc、子系统参考和生成目录；确认声明的持久化类型变更。遵循[测试策略](../../../../docs/testing.zh.md)和[按范围选择检查的规则](../../../skills/dsh-pre-push-checks/SKILL.md)。退出条件：下方验收矩阵通过，无法获得的真实提供方验证证据明确列出。

8. **实现后评测。** 使用现有文件工具与 `apply_patch` 分别执行同一组典型编辑任务，控制模型、仓库状态和任务指令。测量最终文件正确性、任务成功率、请求/prompt/输出 token、模型步骤、工具调用、重试、延迟和现有 Review 覆盖情况。报告失败及收益，包含首个请求的 prompt 成本。退出条件：形成可复现的比较与默认启用建议；不预设改进，也不在本功能中建设通用评测平台。

### Review 验收范围

Review 使用首次修改前与轮次结束时的完整文件采集；工具调用的 hunk 和补丁文本不能代替这些字节。测试应同时覆盖无 Git 仓库及 Git 不可用的环境，避免 Git 覆盖掩盖工具路径漏采集。文件在同一轮次中先创建后删除，或修改后完全还原，没有净变化，可以不产生文件行。

[现有 Review 决策](../../implemented/feature/2026-09-15-changed-file-diff-preview.zh.md)负责大小、数量、时间限制、采集错误行为、会话生命周期及支持位置。本功能沿用这些规则。验收覆盖 Session 可用期间支持范围内的 Host 文件，不承诺持久化或 SSH Review。补齐 SSH 文件系统提供方的操作是为了保持文件系统 API 完整，不代表支持远程 Review。

## 考虑过的替代方案

**继续通过 shell 或 Python 应用补丁。** 无 Git 文件变更仍然缺少可预先确定的修改路径列表，也无法提供所需的模型文件编辑工具。

**复用 Codex 标记，自行实现严格匹配器。** 这可以减少初期实现工作，但会让熟悉的补丁以不同方式失败。已确认设计遵循固定版本 Codex 的解析器和匹配器，并明确记录 Harness 文件系统策略的差异。

**让整个补丁具备事务性。** 跨文件回滚需要恢复状态，并可能覆盖并发的外部编辑。预检加顺序提交可以提前拒绝错误，并提供明确的部分结果，无需承诺回滚。

**添加工具时同时扩展 Review。** 重命名 UI、持久化存储、远程采集和新采集失败策略是独立的产品决策。现有采集与 diff 渲染足以支持本次范围内的工具接入。

## 验收标准

| 领域 | 必需证据 |
|---|---|
| 文本操作 | 新增、更新、删除、移动、多文件和多 hunk 产生预期最终字节；语法与匹配差异有记录。 |
| 受保护的修改 | 未观察或已过期的源文件、受限路径及目标冲突遵循选定策略；预检拒绝不发生写入。 |
| 失败与取消 | 前序提交后的失败报告全部已完成修改和待执行操作；磁盘状态与输出一致。 |
| 无 Git Review | 现有 Review 在轮次结束时展示支持范围内的净变化，包含移动两端对应的现有文件条目；不改变展示逻辑。 |
| 工具体验 | 普通调用和 PTC 使用注册工具；精简输出、错误、工具调用展示与 Session 快照一致。 |
| 启用依据 | 实现后的比较先报告正确性和总工作量，再建议扩大启用范围。 |

## 风险

上游匹配可能较宽松，也可能随版本变化。固定参照版本，并用兼容性 fixture 核对其行为；修复与参照实现不一致的意外差异。任何匹配策略调整都必须记录为已确认设计的变更。复制上游代码还需要审查许可证和依赖。

预检成功后仍可能发生版本冲突、取消或存储失败。提供方保护条件和准确的部分结果必须在这些失败下得到保留，尤其是移动；此处测试失败会阻止工具验收。

路径提取可能偏离执行行为或遗漏移动的一端。在支持 Review 的 profile 中启用工具前，必须共享解析结果并验证完整的无 Git 路径。

本提案保留[文件系统拆分](../../implemented/simplification/2026-06-26-fsspec-style-fs-seam.zh.md)、[观察事件策略](../../implemented/architecture/2026-06-26-file-context-as-event-gate.zh.md)、[文件系统沙箱](../../implemented/feature/2026-07-14-cross-family-fs-sandbox.zh.md)和[轮次变更文件卡片](../../implemented/feature/2026-09-11-turn-changed-files-card.zh.md)的决策依据。它新增编辑能力，不替代上述决策。
